The repo root also has: `vehicles/catalog/` (18 `*.vehicle.json` profiles; the
firmware only builds in `obd2.generic`, the rest install on demand from SD /
App / the vehicle page), `contracts/` (signal table, vehicle JSON schema,
rules-engine golden vectors), `test/host/` (9 pure-C unit-test suites),
`tools/vehicles/` (legacy-table → JSON converters and golden-fixture
generators), `bootmedia/slot_a/` (legacy animation source, generating
`build/bootmedia.bin` for SD installation).

The current I2C definitions use two buses: the main bus uses SCL GPIO10 / SDA GPIO11 on V1 and SCL GPIO8 / SDA GPIO7 on V2/V3; CST816 touch creates a separate bus using SCL GPIO3 / SDA GPIO1 on all hardware versions. See `I2C_Driver.h` and `CST816.h` and check the actual wiring before changing hardware.

The main-bus register wrapper caches up to eight devices and serializes registration. Registration failure or a full cache returns an error instead of aborting firmware or repeatedly leaking device handles. Writes send the register and data in one multi-buffer I2C transaction, avoiding a task-stack allocation proportional to input length.

### TPMS pairing scan lifecycle

`ui_bluetooth.c` provides two entries above the version page and per-wheel pairing views; scan rows contain only six-digit IDs, saved to the current wheel on tap. `tpms_ble_client` registers GAP / shutdown callbacks through `BLE_HUB_APP_TPMS` and deduplicates by broadcast ID (MAC is diagnostic only), appending stable candidates without RSSI sorting. Lock-protected snapshots feed an LVGL timer; BLE callbacks never touch UI objects. Entering calls `elm327_ble_yield_scanner(true)` to yield reconnect scanning, and leaving restores it; an established ELM327 connection continues serial polling. Restart is delayed after stopping to avoid the controller's asynchronous stop.

`tpms_fbb0.c` is a platform-independent parser based on static analysis of TireKing Android `com.zl.dev.tire.king` 1.1.8 / 3538. Independent complete raw records require at least 26 bytes and prefix `02 01 06 03 03 B0 FB`; CRC16-XMODEM covers `raw[9:16] + raw[17:18] + raw[19:26]`, compared against `(raw[16] << 8) | raw[18]`. ID is `raw[25:22:-1]` formatted as six uppercase HEX digits. Pressure is integer Pa: `(raw[12] + (raw[17] == 1 ? 256 : 0)) * 3144`; temperature is `(unsigned)raw[13] - 55`; voltage mV is `raw[11] * 10 + 1220`. Unknown states retain their raw values. Manufacturer ID `AC00` is not assumed. The scan bridge first checks both ADV / RSP lengths are at most 31, then parses each independently; never concatenate fragments or apply raw offsets to manufacturer substrings. Only verified IDs consume candidate slots, so ordinary BLE devices cannot fill the 20-item table.

NVS retains the old `nvs_user_cfg_t.tpms[4]` MAC layout (offset 96, 39 bytes per record), appending `tpms_sensor_id[4][7]` after the full old `sizeof(cfg)=252`. Empty means unbound; `000000` is valid. Saves merge per wheel. Grow-loading old configurations leaves new fields zero; legacy MAC records prompt re-pairing without ID inference. Only a successful save/delete clears that wheel's old MAC; failures roll back. Saving an ID does not imply online status. Background reception, the default overview and theme bindings share a four-wheel cache; built-in tire-pressure alarms are not provided.

INFO-level `tpms_ble` logs contain valid IDs, MAC, type, RSSI, decoded fields and independent raw ADV / RSP HEX. Each ID is logged on first sight, first nonempty response, then every 5 seconds, reset on rescan, with one full-list warning. Decoding, formatting and log I/O are outside the spinlock; no tasks are created. `test/host/espnow/test_tpms_pairing.c` covers synthetic CRC/fields, short packets/invalid lengths, rejection of fragments, ordinary-device filtering, ID deduplication/MAC rotation, full-table updates, lifecycle, log throttling/lock constraints, NVS boundaries and save rollback. The real LVGL `tpms_ui` test enabled by `-DEH_TPMS_LVGL=ON` covers four-wheel ID saving, exact ID-only row text, preservation on cancellation/failure, legacy re-pairing, deletion, rescan and cleanup; `TPMS_UI_CAPTURE_DIR` outputs page PPM files. These tests do not validate physical sensor compatibility.

`lvgl_runtime.c` calls `tpms_ble_service_step()` every 250 ms in the LVGL control context; slaves, devices without an ELM binding, or an established ELM connection allow unlimited background scanning. Manual pairing pauses background scans and restores them on exit; ELM reconnection has priority, with a 500 ms cooldown after stopping and 2-second retries after start failure. Advertisement callbacks update bound IDs even when all 20 candidate slots are full; only CRC-valid samples refresh age, and measurements expire after 120 seconds while diagnostic history remains. Successful rebinding clears that wheel's cache; save failure preserves it. Live values are neither written to NVS nor synchronized through ESP-NOW.

`ui_tpms.c` implements a minimal default overview (two-decimal bar / C / estimated battery, no IDs) and tap-through details. `tpms_theme_source.c` supplies 16 firmware-local sources per wheel: `tpms.fl.*` / `tpms.fr.*` / `tpms.rl.*` / `tpms.rr.*`, without appending to `contracts/signals.json`, OBD PIDs, NVS slots or wire protocols. Themes take one snapshot per frame, using separate extended arrays and paired 64-bit used/change masks (at most 128 sources), supporting conditions and change rules. Legacy `tr_inputs_t` / `tr_eval()` are unchanged; high change bits use `tr_eval_extended()`. TPMS does not follow OBD sweep animation or become invalid merely because the OBD link is absent. The battery helper reproduces TireKing float32 voltage bins as a display estimate only; see [THEMES.en.md](THEMES.en.md) for fields, units and NaN semantics. The frontend is unchanged.

Additional host coverage exercises background priority/cache expiry/full candidate lists/rebind rollback, two-decimal minimal cards and details, every four-wheel theme field, all 256 voltage bytes and boundaries, high-bit change triggers and sweep isolation. Captures use synthetic data, not vehicle validation.

### Boot order (`main/app_main.c`)

```
cJSON hooks (PSRAM; internal RAM only as a fallback once PSRAM is exhausted)
→ nvs_app_init → nvs_storage_init → signal_store_init → sd_card_init (warn only on failure)
→ storage_service_boot (first-boot migration or regular config mount; resumes SD theme selection;
  handles boot-time /OBD/IMPORT RESET.TXT / ACTIVATE.TXT / vehicle JSON)
→ coredump_store_boot_check (after the migration — the migration erases the region
  the old bootmedia occupied in the coredump partition)
→ vp_manager_init (falls back to obd2.generic when no vehicle is pending)
→ task WDT 10 s → I2C/EXIO/LCD/LVGL init → ble_hub_init (before the UI) → boot animation
→ ui_init (incl. theme_engine_init) → ui_ext_init → app_event_init
→ role branch: slave = ESP-NOW slave + RaceChrono; master/standalone = ELM327 BLE
  (auto-connect only with a bound MAC) + ADS1115 oil pressure (V1 board only, and only
  when the active vehicle profile does NOT read oil pressure over OBD)
  + ESP-NOW master (MASTER only) + RaceChrono
→ storage_service_start (state-based 1/3/10 s SD poll; card jobs fire 5 s after start / on card insert / after OTA ends)
→ bootmedia_serial_start (persistent USB receiver, priority 3)
→ ota_valid task (15 s self-check marks the slot valid)
```

### Data flow

```
ELM327 BLE adapter ──BLE──→ elm327_ble_client (single-thread state machine, driven by the vehicle's vp_engine)
                                   │
                                   ▼
                            signal_store (obd.* / sys.* / veh.*, contracts/signals.json)
                                   │      ←── ads1115_oil_pressure (oil pressure, V1 board, when the vehicle doesn't read OBD oil pressure)
                 ┌─────────────────┼──────────────────┐
                 ▼                 ▼                  ▼
           LVGL page refresh     theme_tick()     espnow_link (master broadcast, v6 TLV)
           (built-in gauges,     (runtime theme         │
            via obd_data_cache)      pages)             ▼
                                              slave espnow_link queue → worker → render
```

Each vehicle profile (`vehicles/catalog/*.vehicle.json`, compiled into a
`vp_profile_t`) declares its own request/decode rules and writes its `veh.*`
slots in `signal_store`; whether `vp_engine` sends an ATMA monitor probe,
switches CAN headers, etc. is driven entirely by the profile — no more
branches hard-coded on the vehicle's name.

**The ELM327 poll loop is a single-threaded state machine**: init →
(optional) protocol auto-detect → poll loop. Never introduce parallel
requests when touching it — one adapter serves one request stream at a time
(an AGENTS.md hard rule).
BLE callbacks wake the polling task with a persistent static semaphore. The BLE shutdown callback also wakes the task to exit; the semaphore survives task deletion so late callbacks do not access a freed task handle.
BLE connection and scan timestamps use a critical section to prevent torn 64-bit reads across tasks on the 32-bit target.

The boot-lifetime LVGL task is pinned to core 1, while the ELM327 BLE polling
state machine is pinned to core 0; task parameters are centralized in the
policy table in `app_main.c` and created through `app_tasks.h`. This keeps gauge/LVGL rendering and OBD polling from preempting
one another on the same core, while the BLE stack continues to follow ESP-IDF
configuration. Do not split or parallelize ELM requests as a consequence.

The LCD LVGL `wait_cb` waits for DMA completion through a boot-lifetime static
binary semaphore instead of spinning on `draw_buf->flushing` during double-buffered
refresh. The completion ISR first releases the buffer with `lv_disp_flush_ready()`,
then signals the waiter. The task must recheck `flushing`: a stale token from an
earlier transfer or fullscreen video is not completion of the current transfer.
Initialize the semaphore before registering the LCD callback; never delete it on
page/video transitions, and do not use LVGL notification slot 0. The ESP-IDF 5.5.3
SPI LCD backend ignores completion callback return values, so the bridge explicitly
requests an ISR yield when waking a higher-priority task. See
`app_obd_dsp/lvgl_flush_sync.c`.

The `bootmedia_usb` receiver runs at priority 3, below OBD polling and LVGL at 4, so busy USB communication does not preempt real-time data and display tasks at a higher priority. USB remains available after normal boot and blocks waiting for input when idle; web flashing, resource upload and management RPC flows remain unchanged.

## Build configuration

Environment: ESP-IDF 5.5.3 + Python toolchain. Component dependencies
(`main/idf_component.yml`): `lvgl/lvgl`, `espressif/esp_lcd_touch`,
`joltwallet/littlefs`, `espressif/esp_new_jpeg` (1.0.2) — pulled into
`managed_components/` on the first build. The `button`/`knob` components
were removed (unused).

```bash
idf.py set-target esp32s3
idf.py menuconfig     # OBD DSP Configuration
idf.py build
idf.py -p PORT flash monitor
cp build/bootmedia.bin /Volumes/SDCARD/OBD/BOOT/bootmedia.raw
```

> **After changing `sdkconfig.defaults`, delete the local `sdkconfig` before
> the next build** (`defaults` only takes effect while generating a fresh
> `sdkconfig`; it never overwrites one that already exists). Defaults this
> change touches: `CONFIG_FATFS_LFN_HEAP`/`CONFIG_FATFS_MAX_LFN=255` (SD long
> file names), `CONFIG_ESP_COREDUMP_ENABLE_TO_FLASH` + `_DATA_FORMAT_ELF` +
> `_CHECKSUM_CRC32` (crash dumps), `OBD_SD_SLOT_*` (see the table below).

The device's own web page (`device_web_page.html`, OTA mode only) is
gzip-embedded at build time by `tools/gzip_asset.py`; the compressed size has
a hard cap of **48 KB** and the build fails above it.

`menuconfig → OBD DSP Configuration`:

| Option | Values | Notes |
|--------|--------|-------|
| Hardware version | **V1** (default, this refactor's target board) | Waveshare ESP32-S3-Touch-LCD-1.85: ST77916 v2 init + TCA9554 + ADS1115 |
| | V2 | New board A: ST77916 **v1** init, direct GPIO, no TCA9554 / ADS1115 |
| | V3 | New board B: ST77916 v2 init, direct GPIO, no TCA9554 / ADS1115 |
| SD card slot | **SDMMC 1-bit** (V1 default) / None | V1 uses SDMMC 1-bit (CLK14/CMD17/D0 16); boards with None report "no card" for every SD feature |

> Brake temperature (RS485) and its BLE OTA service were removed in this
> refactor — see CHANGELOG.en.md.

The build runs `tools/gen_themes.py` at CMake configure time to generate the
theme table, and injects the git branch / commit count / short hash as
`OBD_GAUGE_BUILD_TAG` (this is the build tag shown in the device manifest and
on the version page — so commit *before* releasing, see
[release workflow](#release-workflow)).

## Porting a new board

1. Add a hardware-version option in `Kconfig.projbuild` (if LCD / touch /
   IO expander differ)
2. Focus on `bsp_obd_dsp/`: `lcd_driver/` (init sequence, QSPI parameters),
   `touch_driver/`, `exio/` (IO expander present?), pin definitions
3. Resolution / color-depth macros live in `ST77916.h`; the UI assumes
   360×360, so a different screen means touching `export_path/`
4. Nothing vehicle-related needs to change — car logic lives in
   `main/vehicle/` (engine/lifecycle) + `vehicles/catalog/*.vehicle.json`
   (the actual vehicles), independent of the board

Example Car Scanner conversion (the PID catalog is an aggregate index; per-vehicle generation uses each vehicle entry's own `pids`):

```bash
python3 tools/vehicles/import_car_scanner.py \
  --profiles /path/to/vehicle-profiles.json \
  --output /tmp/carscanner-community

```

The converter accepts direct `21xx` / `22xxxx` requests and decoding that the firmware can express: linear `MUL/DIV/OFS`, reverse byte order, and simple arithmetic, `And`, `Shr`, and single-byte `SIGNED` formulas. Conditional branches, `FLOAT32`, formulas combined with external scaling, complex initialization commands, and firmware-unsupported requests are reported in `summary.json`. It defaults to 12 custom signals per profile; all 820 outputs from the current 1,304-profile input passed firmware catalog validation and the 8 KB NVS blob limit, while larger profiles may exceed that limit. Output vehicle JSON files can be imported and published individually in the vehicle community; make, model, and year metadata are retained for filtering.

### PID-hunting workflow (find private PIDs without a car)

To discover private PIDs (oil temp, oil pressure, gear, …) for a new car,
reverse-record what a phone app sends through the fake adapter (Car Scanner
ships per-car profiles):

```bash
python3 tools/one_shot.py
# 1. starts fake_elm327.py --probe prbs --tick 2 (injects known pseudo-signals)
# 2. on the phone, connect Car Scanner to the WiFi ELM327 (your IP:35000),
#    pick the target car profile, record a session and export the CSV
# 3. paste the CSV path; the server stops and the analysis runs → pids_full.csv
```

How it works: the fake server answers every unknown PID positively (so the
app never marks it unsupported and asks its whole profile), and each injected
signal corresponds to one real app request — pairing them in order recovers
which PID drives which gauge and its decode formula. For how to turn that
into an `rpn` formula, see [PID_GUIDE.en.md](PID_GUIDE.en.md); then feed the
results into a vehicle profile per
[VEHICLES.en.md](VEHICLES.en.md#adding-or-editing-a-vehicle).

## Host unit tests and CI

`main/vehicle/`, `main/theme_engine/`, `main/media/` (OBV1),
`main/bsp_obd_dsp/espnow_v6.c` and other pure-C modules have no ESP-IDF /
FreeRTOS dependency, so they build and run on the host — no device, no
`idf.py` needed:

```bash
cmake -S test/host/<suite> -B build/host/<suite> -G Ninja
cmake --build build/host/<suite>
ctest --test-dir build/host/<suite> --output-on-failure
```

`<suite>` is one of the directories under `test/host/`: `rules` (rules
engine, 38 golden vectors + output-cache comparisons), `vehicle` (vehicle RPN compile/validate +
golden request sequences), `espnow` (v5/v6 codec + RaceChrono filter scheduling), `media` (OBV1 parser +
legacy delta stream + CRC comparisons + real-player control waits), `engine` (the vehicle polling engine, golden request
sequences), `theme` (theme engine: layout/overlay/sidecar/pixel conversion; theme_tick caches the active page and indexes dynamic bindings), `signal_store` (batched reads, staleness checks, and performance histograms),
`storage` (real storage service, slot/no-slot configurations, boot/hotplug/OTA/retry timing; SDK/RTOS boundary stubs).

`signal_store` also contains delivered-unit conversion comparisons: `SS_SANITIZE=ON` (the
default) enables ASAN/UBSAN, and `SS_DELIVERY_BENCHMARK=ON` builds the conversion benchmark.

## Release workflow

Run `./tools/release.sh "fix: describe change"` on the development branch (for example `rebuild`), then merge source, artifacts and manifest into `main` and push `main` to publish. The script activates EIM and performs source commit → `idf.py reconfigure build` → manifest generation → separate `build:` artifact commit → `git push --no-verify`. Both commits use `--no-verify`. Automatic source staging excludes `build/`, `firmware/release/` and both CHANGELOG files; review the remaining staged scope before running. Local and server branches need not match: optional local `FIRMWARE_BRANCH` restricts the build branch, while the server defaults to watching `main`.

Fast-forward and normal merges preserve the original build branch tag. If merging changes source or squash/rebase rewrites the build history, rebuild on the final `main`. The firmware tag and manifest reference source commit N; the artifact commit is N+1. The server verifies N is an ancestor of the checkout and permits only whitelisted artifacts after N, preventing stale binaries from being labeled as new source. `gen_release.py` validates the complete NUL-terminated tag, sizes and optional raw bootmedia before staging files and replacing `latest.json` last. Validation failure leaves the existing release intact. Without `build/bootmedia.bin`, the manifest omits it and removes the stale published copy. Custom media still installs on SD.

```text
firmware/release/
  latest.json
  obd_brz_gauge.bin
  bootloader/bootloader.bin
  partition_table/partition-table.bin
  ota_data_initial.bin
  bootmedia.bin                         # optional legacy SD payload
```

The store server uses a dedicated firmware checkout, fetches `origin/main` every 60 seconds, and validates SHA256/size and source version from `firmware/release/latest.json`. It uploads versioned files, writes the database, then updates `PUBLIC_BASE_URL/firmware/esp32/latest.json`. Failures retry next cycle; successful state persists. The Docker watcher does not compile IDF. Web and App use the same manifest. For deployment and Android source/build/artifact commits and server checkout updates, see `docs/RELEASE_GUIDE.en.md` in the store repository.

## Commit conventions

- Record behavior and flashing changes in [CHANGELOG.en.md](../CHANGELOG.en.md)
- New fields in NVS `nvs_user_cfg_t` / theme structs are **appended at the
  end only** (on-device NVS compatibility)
- Never hand-commit `ui_theme_generated.c` / `theme_assets/` (generated files)

### Bilingual documentation rules

- Docs are maintained in pairs: `X.md` (Chinese, the **source of truth**) ↔
  `X.en.md` (English translation). Every fact change goes into the Chinese
  file first, then the English file follows in the same commit
- Structure is mirrored 1:1 (sections, tables, code blocks) so the two stay
  easy to diff against each other; commands, code, JSON, log output and table
  data are never translated
- Inside English docs, links to other documents point at their `.en.md`
  versions; links to code and partition files are unchanged
- Every paired file carries a language-switch line under its title
  (`English | [简体中文](X.md)`); when adding a new document, create both
  languages together

The multi-gauge master protects slave presence and protocol-version records with one critical section shared by the radio callback and readers.

The ESP-NOW slave DATA callback copies raw payloads into a persistent eight-frame queue. The slave worker alone decodes packets, writes signals and checks timeouts. A full queue drops new frames and the worker logs a warning. Consumption rechecks the bound MAC and receive time so expired packets cannot restore online status. Both master and slave workers exit cooperatively for OTA: `espnow_link_pause_for_ota()` returns false until they finish, and LVGL retries on a timer before starting the hotspot, without waiting or forcibly deleting a task holding resources. The queue and wake semaphores remain alive for the boot session.
