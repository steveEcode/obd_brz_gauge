# 使用指南

[English](USER_GUIDE.en.md) | 简体中文

编译烧录见 [FLASH.md](FLASH.md)，连不上先看 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)。

网页刷机页和车型社区的所有仪表操作均通过 ESP32-S3 原生 USB：刷写固件、安装主题/动画、删除当前主题、安装/启用车型及重启。无需输入设备地址、连接热点或开启 OTA；先升级支持 USB 管理的新固件，正常开机后在网页操作按钮中选择串口。使用 Chrome/Edge，网页需为 HTTPS 或 localhost。CH340/CP210x 可刷固件，但不支持应用态资源与管理操作。社区浏览、登录、下载和发布仍使用网络；App WiFi OTA 保持兼容。

固件同时修复 ESP-IDF 5.5.3 的 LCD SPI 锁唤醒遗漏，避免开机视频卡在末帧；已有动画与透明图片主题不需要重新导出，更新固件即可。

## 首次开机

1. 上电后背光保持关闭，直到 Sky Gauge Logo 首帧传输完成并留出 50 ms 面板扫描稳定时间后再点亮；随后按设置的开机模式进入（默认 RACE 动画，可关）
2. 先通过网页或 App 安装车型与主题；车型可在仪表 VEHICLE 页启用，主题可在 Settings 的 THEME 中选择
   - **BOOT PAGE** 选开机默认停留的页面
3. 到 **版本页上滑 → ELM327 PAIRING → BLE SCAN**，扫描并选中你的 ELM327 BLE 适配器
4. 连接成功后仪表自动初始化（自动协议检测见 [TROUBLESHOOTING.md](TROUBLESHOOTING.md#协议自动检测)），数据开始刷新

之后每次上电仪表会自动回连上次的适配器（记忆 BLE 名称 + MAC），数据中断也会自愈重连，
正常情况下**上车通电即可，无需任何手动操作**。

网页车型社区支持下载、收藏和编辑。网页设备操作使用 ESP32-S3 原生 USB：安装车型、查看警告后，再单独设置下次启动车型并请求重启。主题包通过网页 USB 或 App WiFi OTA 安装，已注册主题在 Settings 的 THEME 中选择。请先核对车型适用性，所有操作在停车时进行。SD 卡由固件后台管理，用户无需取卡或手动整理文件。

网页刷机页的 **删除当前主题** 会删除当前主题包及 SD 卡 `/OBD/THEMES/<key>/` 下的专属资源，并在重启后恢复内置默认主题。此操作需要 SD 卡正常挂载；不会删除其他主题或公共开机动画，且删除后不能从设备恢复。

## 页面导航

仪表主界面是一个**轮播环**，左右滑动切换，环上的页面（左滑 = 下一页）：

主题页面的图片、视频和其他内容区域会把手势交给主题页面本身，因此从主题内容的任意位置左右滑动
都可以切换到下一页或版本页。主题默认页会在 Logo / 开机动画显示期间后台读取并转换图片，屏幕继续
显示 Logo / 动画；开机视频等首帧完整传输到 LCD 后才替换 Logo；播放期间界面更新不会清掉启动画面。如果开机视频先于主题准备结束，会返回 Logo 等待页面就绪。视频期间不创建主题控件，准备完成后
才由 LVGL 创建并切换表盘，避免透明图片转换期间卡在末帧或打断视频；视频解码失败或被中止时立即恢复 Logo，
主题准备失败则回退到内置页面。主题图片从 SD 批量读取，避免透明图加载期间逐字节读取造成长时间等待；已有主题包无需重新导出。

```
        ┌──────────────────────────────────────┐
        │  GEAR → RPM → SPEED → TEMP → INFO →  │
        │  NEEDLE → CHART → TPMS → 版本页 → GEAR │
        └──────────────────────────────────────┘
```

| 页面 | 显示内容 | 下滑进入的子页 |
|------|----------|----------------|
| GEAR | 挡位（大字）+ 转速 | 运行时主题表盘页（仅加载了带页面的主题分区主题时出现）|
| RPM | 转速弧 + 超限红色闪烁 | RPM 报警阈值 / 闪烁开关 |
| SPEED | 车速 + 里程统计（运行时累计）| — |
| TEMP | 水温 / 油温 / 进气温（可自定义映射）| 3 行数据项映射配置 |
| INFO | 多格信息面板（可自定义映射）| 5 格数据项映射配置 |
| NEEDLE | 指针表（下滑切数据源）| 指针页数据源选择 |
| CHART | 曲线页 | 下滑曲线源配置 / **上滑报警阈值** |
| TPMS | 四轮压力 / 温度 / 电量 | 点击轮位查看完整诊断数据 |
| 版本页 | 固件 build tag、BLE 连接状态与设备名 | 见下方隐藏入口 |

运行时主题有多页时，左右切页先在后台准备目标图片，当前页保持显示和刷新，准备好后再切换。准备中重复切页不会排队；离开页面会取消本次跳转，失败时保留当前页。字体和控件创建仍可能带来短暂停顿，实际速度也受 SD 卡和可用内存影响。

**版本页是功能枢纽**：

- **上滑** → BLUETOOTH PAIRING，选择 **ELM327 PAIRING** 或 **TPMS PAIRING**；从表的第一项为 **GAUGE MASTER PAIRING**，进入 FIND MASTER 扫描
- **下滑** → 设置页
- **OTA 按钮** → OTA 升级模式（见 [FLASH.md](FLASH.md#app-ota-升级（双槽回滚）)）
- 左右滑 → 回到仪表环

**隐藏入口**：

- **Logo 页双击** → OBD 协议选择滚轮（**长按 2 秒**保存并重启；协议 0 = 自动检测，检测结果不再覆盖自动选择；旧版本已保存非零协议时需重新选择 0 一次）
- **版本页快速连点 10 次** → 展厅演示模式（扫表动画）

数据超时或蓝牙断开时，仪表页会显示 **NO SIGNAL** 提示。

蓝牙连接后的自检扫表按实际经过时间推进，目标刷新间隔为 16 ms，而不是每回调一次才前进一步。绘制繁忙时会跳过过期的动画位置，不再拉长整段扫表；主表标称总时长为 1.92 秒，结束帧恢复配置亮度与真实数据。三连表从表在同步包之间补齐动画位置，闪光和结束仍以收到的主表步号为准。该变化不提高真实 OBD 采样率，也不保证屏幕达到 60 FPS。

转速、车速、涡轮压力和节气门会按当前页面需要优先采集；内置数字页、车速页与指针页中的这些数据及负载直接显示最新样本，减少逐步追赶造成的滞后。温度等慢参数仍保留显示平滑。实际更新速度受适配器、ECU 和车型配置的最小采集周期限制。

**BLE SCAN 页删除已保存设备**：点列表里已保存设备旁的 ✕ 会立即断开当前的 ELM327
连接并清空保存的名称 / MAC，**不会自动重连**；需要重新扫描选中才能再连接。
从表（SLAVE）在 **FIND MASTER** 页做同样操作时，解绑的是主表并重新开始扫描。

## 蓝牙胎压传感器配对

在版本页上滑，选择 **TPMS PAIRING**，再给每个轮位单独选择传感器：

| 轮位名称 | 对应车轮 |
|----------|----------|
| FRONT LEFT | 左前 |
| FRONT RIGHT | 右前 |
| REAR LEFT | 左后 |
| REAR RIGHT | 右后 |

1. 点击轮位，再点 **PAIR SENSOR**，唤醒该轮的传感器，等待扫描结果。
2. 列表只显示通过 TireKing FBB0 固定头和 CRC 校验的六位编号，例如 `18010F`。不显示普通蓝牙设备、广播名称、MAC 或 RSSI。编号来自广播里的传感器 ID，不是改名后的蓝牙设备名，也不从 MAC 推算；前导零保留。每轮扫描最长 20 秒，最多列出 20 个不同的有效 ID。
3. 核对传感器标签后，**点击编号就保存到当前轮位**，无需另按确认。编号保存在 NVS，重启保留；同一编号不能重复分配给其他轮位。轮位列表显示保存的编号，详情页标注 `ID SAVED - waiting for broadcasts`，仅表示已登记，是否在线以接收广播为准。
4. 已保存的轮位可以 **RE-PAIR** 重新选择，或 **DELETE PAIRING** 删除。取消重扫、返回或写入失败不替换原绑定；删除只影响当前轮位。

点 **BACK** 或左右滑动返回上一级；扫描页的 **SCAN AGAIN** 可重扫。进入胎压页面会暂让 ELM327 停止自动重连扫描，退出后恢复；已有 OBD 连接和串行轮询继续运行。

旧版仅保存 MAC 的记录保留兼容，但无法可靠换算成传感器 ID：轮位显示 **RE-PAIR**，详情显示 **LEGACY RECORD**，请重扫保存或删除，不会自动猜测 ID。换成 ID 绑定后，MAC 改变不影响同一编号的识别。

当前只接入 TireKing FBB0 广播主路径：扫描时直接解析胎压、温度、电压和状态，不发起 GATT 连接或安全配对。保存后支持后台接收和仪表显示，但不包含胎压报警。其他 TPMS 协议未通用支持。协议依据 APK 静态分析与构造报文测试，实际标签与广播编号是否一致、休眠/唤醒及广播周期仍需这只实物验证。CRC 只是报文完整性检查，不是身份认证。

### 四轮胎压总览

默认页面环在 **CHART → TPMS → 版本页** 之间增加四轮总览，`FL` / `FR` / `RL` / `RR` 分别为左前、右前、左后、右后。总览与 INFO / TEMP 页统一为主题背景、细灰分隔线、蓝色轮位标签、白色大号压力读数和灰色辅助信息；`TIRE PRESSURE` 使用较小的灰色标题并留出圆屏边框间距，不再显示 `Tap tire for all data` 提示。总览不显示六位编号，只保留轮位、压力（**bar，保留两位小数**，例如 `2.10`、`2.25`）、温度（`C`）和估算电量（`%`）。未绑定、未收到或距离最后一次有效广播达到 120 秒时显示 `--`，不把历史数值当成实时读数。

点击轮位可查看编号、接收状态、压力原始值、温度、电压、状态码、版本、RSSI、地址类型、MAC 和最后接收时间；过期数据标记 `STALE` / `cached`。左右滑或点 **BACK** 返回总览；总览左右滑继续切页。在设置页 **BOOT PAGE → TPMS** 可将胎压总览保存为内置页面的默认启动页；自定义主题仍优先进入其默认页，原有未配对设备的启动配对流程不变。

保存任一轮编号后，在蓝牙可用且无需优先连接 ELM327 时自动后台扫描；手动配对或 ELM327 重连优先，不中断已建立的 OBD 轮询。120 秒是界面有效期，不代表设备实际广播周期。休眠的传感器需唤醒后才可能更新；后台扫描和配对页共用同一广播解析器，不建立 GATT 连接。

电量按照 TireKing 电压分档估算，不是广播直接上报的真实剩余容量：电压先转 float32，再提升为 double，依次严格比较 `>2.8` / `>2.6` / `>2.4` / `>2.2`，对应 `100%` / `75%` / `50%` / `25%`，其余 `0%`；十进制阈值受 float32 边界影响。完整电压仍在详情页可见。运行时自定义主题可使用 `tpms.*` 数据源，见 [THEMES.md](THEMES.md)；本次未改前端编辑器。

### 扫描日志排查

使用串口监视器（`idf.py -p <port> monitor`）记录日志，再进入轮位的 **PAIR SENSOR** 或 **RE-PAIR** 扫描页，搜索 `tpms_ble`。可看到扫描请求、结束/失败/取消，以及有效传感器的 ID、MAC、地址类型 `type`、RSSI、`pressure_pa`、`temp_c`、`voltage_mv`、状态和版本，另附完整原始广播 `ADV` 与扫描响应 `RSP`。原始数据为连续大写十六进制，空数据为 `-`。以下是人工构造数据，不是实测：

```text
tpms_ble: sensor=123456 device=AA:BB:CC:DD:EE:FF type=0 rssi=-55 pressure_pa=251520 temp_c=25 voltage_mv=3000 state=0 version=1 ble_ver=10 ADV[26]=0201060303B0FB12FF0000B250500001F000630A000000563412 RSP[0]=-
```

每个有效 ID 首次出现时输出一次，首次收到非空扫描响应额外输出一次，其后每 5 秒最多一次；重扫重置限频。日志是采样诊断，不是完整抓包。普通设备和校验失败报文不进入候选表，也不输出设备日志；只有 20 个有效 ID 才会占满列表，此时本轮警告一次，已有 ID 仍可刷新。非法 ADV / RSP 长度直接忽略，独立报文不会拼接后强行解析。

若没有目标编号，请记录完整扫描周期，并唤醒传感器后重扫；未出现不能据此断定设备损坏，也可能不是当前支持的协议或尚未发出广播。实际 `18010F` 应来自 `raw[23:26] = 0F 01 18` 且校验通过，不能仅凭原始数据偶然出现相同字节认定。日志含设备地址，公开分享前注意隐私。

## 设置页

| 设置项 | 说明 |
|--------|------|
| BOOT PAGE | 开机默认页（TEMP / INFO / CHART / NEEDLE / GEAR / RPM / SPEED / TPMS）|
| VEHICLE | 打开车型页，查看已安装配置并选择启用；切换后按页面提示重启生效 |

| 亮度 | 10–100% |
| RACECHRONO | ON=完整 BLE 服务（RaceChrono + 配对）；OFF=最小模式（主表只保留配对服务并广播，其他角色不开 BLE 服务、不广播），省内存 |
| 下滑 → MULTI-GAUGE | 三连表角色与开机动画设置（见下）|

**下滑进入 MULTI-GAUGE、左 / 右滑返回的手势不变**。

所有设置存 NVS 断电不丢。里程 / 行程统计只在本轮通电内累计，重启清零。

## 车型、主题与 SD 存储

车型配置的安装和导入通过网页或 App 完成，也可在仪表的 VEHICLE 页面选择已安装的配置并启用。切换车型通常在设备重启后生效；网页或 App 会显示安装、启用和重启状态。出现车型验证失败或安全模式时，请按网页 / App 的设备状态提示恢复 Generic OBD2，或联系维护者。主题可在 Settings 的 THEME 滚轮中选择；主题包安装仍通过网页或 App 完成。

固件在后台使用 SD 卡保存车型配置、主题包及图片、字体、视频等媒体资源，并自动处理导入和迁移。仪表不提供 SD 浏览、导入或弹出操作；请不要在运行中取卡或手动修改卡内文件。没有可用 SD 资源时，固件会按回退策略使用内置界面和可用配置。

网页主题编辑器点击 **导出主题 ZIP**，会下载一个包含主题和配套资源的 ZIP。插好 SD 卡，进入网页刷机页连接设备，
在 **主题** 区域点击 **本地上传** 选择该文件，即可安装并自动切换、重启；也可点击 **从社区选择** 安装社区主题。
兼容旧版 BIN，可同时选择配套 JSON 和 `.obv`；仅有 BIN 无法恢复未提供的规则或视频。首次使用需要更新支持此功能的固件，
主题上传使用 ESP32-S3 原生 USB 接口；无需用户在仪表上管理 SD 文件。完整固件刷写后先重连，再安装主题或动画。

## 三连表（ESP-NOW 联动）

一块 ELM327 适配器只允许一个蓝牙客户端，所以多块表采用**一主多从**：

- **主表（MASTER）**：保持 BLE + ELM327 连接读数据，通过 ESP-NOW 广播解析后的数据
- **从表（SLAVE）**：只收广播渲染，零额外 OBD 负载
- **独立模式（默认）**：不启用 ESP-NOW

三块板烧同一份固件，角色在 **设置页 → 下滑 → MULTI-GAUGE** 里选（重启生效）。

**配对流程**（真蓝牙配对，不是盲收广播）：

1. 主表设为 MASTER，开始广播 `SkyGauge-XXYY`（XXYY 为设备后缀，多车同场不冲突）
2. 从表设为 SLAVE；未配对过时开机会直接进入 **FIND MASTER** 扫描页
3. 在列表里选中要跟随的主表，完成绑定（记忆主表 MAC，之后每次开机自动跟随）

三连表还支持**联动转速报警**：超阈值时三块表按表位依次亮起再全体闪烁
（RPM 报警页里可开关 Linked 模式），以及开机 "RACE / AS / ONE" 同步动画。

主表会合并在线从表当前页面注册的 `obd.*`、`veh.*` 和 `tpms.*` 数据需求。副表切换到涡轮、油温等页面时，主表会在下一轮同步中补采所需 OBD 信号；车型扩展值继续广播全部有效值，从表不额外连接 OBD，也不会各自发起轮询。`sys.*`（角色、页面、运行时间等）保持各表本地含义，不复制主表系统状态。

**胎压只需在主表配对**。新版从表进入默认 TPMS 页自动注册四轮；自定义主题的标签、指针、视频或规则引用任意 `tpms.<wheel>.*` 字段时，自动注册对应轮位，不要求主表也停留在胎压页。主表每 500 ms 转发已注册轮位的完整快照，压力、温度、电量和诊断详情共用该快照。从表不需要重复绑定，也不后台扫描本机旧绑定；这些本机绑定不会被覆盖，但从表显示只采用主表数据，不混入本地旧值。

切页会替换需求；从表退出或停止上报后，主表在 2 秒需求窗口到期时撤销其注册。连续 2 秒没有胎压扩展帧，从表清空主表胎压视图并显示 `--`；传感器 120 秒过期限制仍独立生效，重复转发不会重置传感器数据年龄。重新绑定主表或退出 ESP-NOW 时也清空旧胎压。胎压转发要求主表与接收的从表均升级到支持此扩展的固件；组内其他旧从表不会阻止新从表接收胎压，但旧主表不能转发胎压。

RPM 报警页的 TEST 由主表统一生成渐变；主表/从表再次按 TEST 都会重新开始。
主表收到请求后会缩短闲时广播等待，但两批广播之间仍至少等待 20 ms；主表进入 OTA 后不再启动测试。

**混合版本兼容**：主表只有在每块在线从表都支持 v6 时才广播 v6 格式的数据帧，
只要有一块从表还是老固件就退回 v5；所以三块表可以一块一块轮流升级，不用同时刷。
挡位数据要全部表都是新固件才会显示；车型相关字段（`veh.*`）只在从表装了与主表
相同车型（id + 版本号一致）时才显示。联动报警用的控制包始终是 v5，不受影响。

## 开机动画

**设置页 → 下滑 MULTI-GAUGE → INTRO** 滚轮选三种模式（存 NVS `intro_enable`）：

| 模式 | 效果 |
|------|------|
| OFF | 跳过动画直接进仪表 |
| RACE | 内置 "RACE AS ONE" 动画（三连表同步）|
| VIDEO | 播放公共 SD 开机媒体，与当前主题无关 |

VIDEO 模式读取公共 SD 目录：

1. `/OBD/BOOT/boot.obv`，其次为 `/OBD/BOOT/boot.jpg`，最后是旧格式 `bootmedia.raw`。

`boot.obv` 用 `python3 tools/make_video.py boot INPUT -o boot.obv` 制作。
主题编辑器的媒体资源面板只管理页面/事件使用的图片和视频；开机动画不属于主题。网页原有上传流程
仍写入公共 SD 目录 `/OBD/BOOT/`。USB
刷写页连接设备后，在 **开机动画** 区域选择 **从社区选择** 或 **本地上传**；本地支持常见视频格式（包括 MP4、MOV、WebM、MKV、AVI、WMV、GIF）、OBV2 `.obv`、
编码后的 ZIP、同时选择 manifest 与媒体 BIN，或包含 4 KiB manifest 头的旧 raw 镜像。H.264 MP4 在浏览器
使用 WebCodecs 解码；其他视频按需加载约 31 MB 的单线程 FFmpeg WebAssembly 核心在浏览器本地解码为无损 PNG，
再以 360×360 画布（保持比例、不裁切）编码为 Q90 baseline JPEG 4:2:0，经 USB 上传为 OBV2 存入 SD。源帧时间戳和可变帧率间隔会保留。
仅支持 FFmpeg WebAssembly 构建可解码的输入；加密、损坏素材或浏览器内存不足时会报错。每帧上限 128 KiB，格式帧率上限 60 fps，动画总大小上限 256 MiB，
不代表硬件保证达到该帧率。超过 48 KiB 的帧需要升级到支持 128 KiB 上限的固件；原有小帧动画仍可使用。超出文件、缓存或帧大小预算时会提示，不会静默降低质量或帧率。USB 本地导入的源视频不会上传到社区或服务器，`.obv` 可直接上传。
开机动画社区的 **上传** 使用同样的 360×360 / Q90 编码，默认保留源帧率，并支持裁剪、缩放、截取和手动选择帧率；社区发布会上传源视频作为预览。
播放暂时落后时，固件跳过已经过期的中间帧以追赶时间轴，保留首尾帧，不再因连续迟到而提前结束。
网页校验后将设备复位到应用态，通过 ESP32-S3 原生 USB Serial/JTAG 上传到 SD。上传成功后会使用本次动画并删除其他旧格式的公共开机动画；传输中断、SD 写入同步失败或校验失败时保留当前动画，旧文件清理失败会提示错误。CH340 / CP210x 外置串口可刷固件，
但不支持此动画上传。开机动画上传要求 SD 卡已挂载且有足够空间；手机 App 仍可使用 WiFi OTA 上传。
无卡或所有文件都不可用则跳过自定义动画。旧 raw 动画的播放时长由实际帧数和帧率计算，忽略 manifest 中可能过期的时长；
没有主题页且尚未保存 OBD 适配器/主表的设备，会在开机动画期间预建扫描页，并在该页显示后启动扫描，避免动画结束后再同步创建页面。
画布为 360×360，1:1，注意圆屏四角裁切。
旧 Flash 动画不直接播放。上传先写 SD 临时文件并校验，
再安装；FAT 文件替换存在短暂窗口，不承诺掉电原子替换。
替换失败时会尝试恢复旧文件；如果恢复也失败，旧文件保留为目标文件同目录的 `.obd-bak` 后缀文件。请检查 SD 卡并手动恢复，已有备份不会被后续替换覆盖。

## 手机 App 升级

配套 App（`android_app/app-debug.apk`）支持以下推送。Wi-Fi 操作前先在仪表
**版本页 → OTA 按钮** 进入 OTA 模式并连接仪表热点：

- **固件升级**：手机连仪表 WiFi 热点（`OBD-Gauge-OTA-XXXX`，密码 `88888888`）高速传输，
  写入备用 OTA 槽
- **开机动画**：App 内裁切视频、编码后上传
- **主题包**：推送运行时主题到 SD 主题库并保存选择（见 [THEMES.md](THEMES.md)）

主题、开机动画和车型安装/启用以及主题删除优先 Wi-Fi；Android 在 Wi-Fi 失败后自动回退原生 USB，iOS 仅支持 Wi-Fi。Android 回退时会先确认 USB 管理能力；新固件可自动停止 OTA 接收并接管，旧固件需先退出 OTA 模式。OTA 正在启动或停止时，操作会提示稍后重试；等待完成后再操作或滑动退出。主题/动画安装失败保留当前文件，安装成功由固件自动重启；车型安装与启用是两个独立动作。删除主题或启用车型成功但重启未获确认时，App 提示手动重启，不重复执行操作。

Wi-Fi OTA 在 10 分钟无活动后自动关闭；发现设备、查询设备信息和已鉴权的请求都会刷新计时。重新进入时使用新的计时会话。如果无法创建超时监控任务，OTA 会提示启动失败。

设备通过 `GET /ota/info` 暴露硬件 / 构建信息，App 刷写固件前自动做兼容校验，
硬件不匹配会拒绝刷写。协议细节见 [APP_PROTOCOL.md](APP_PROTOCOL.md)。

**固件升级的验证与回滚**：新固件启动后仪表后台有一个 15 秒自检任务，到点才会调用
`esp_ota_mark_app_valid_cancel_rollback()` 把当前槽标记为有效。如果新固件在这
15 秒内重启或崩溃（没能标记有效），下次开机 bootloader 会自动切回升级前的槽位，
相当于自动回滚，不需要手动操作。退出 OTA 模式（往旁边滑走）本身会触发一次重启。

## 清空已安装车型配置

在网页 USB 刷写页的“车型配置”区域，点击“清空已安装车型配置”，阅读范围并勾选确认后，可删除所有已安装车型及 SD 镜像，再重启恢复内置 `OBD2 Generic`。必须插入 SD 卡并升级支持 `vehicle.clear` 的固件；失败不显示清空成功，重启失败可单独重试。主题、动画及 CATALOG / IMPORT / EXPORT 中的车型模板保留。

## 视频提前解码与双缓冲

播放器继续采用 SD 连续预读、PSRAM 压缩帧 ring 和常驻 JPEG 解码器。全屏模式将下一帧的首个 MCU 条带或完整图像提前解码，到源时间点才开始刷屏；两个内部 DMA 条带按奇偶交替，等待上次传输完成后才提交下一条带，不改写在途缓冲。主题叠加模式保留前后台双帧缓冲及 LVGL 交接。OBV2 时间轴同样提前解码，暂停时保留压缩帧并移动时间基准，超时帧按既有规则跳过。解码耗时统计排除等待帧时间点的睡眠。实际帧率仍需在设备上测量；没有硬件测试不能承诺固定帧率。

进入 OTA 时，仪表先停止三连表通信并完成当前任务，热点就绪前可能短暂显示 `WiFi: Starting...`。
