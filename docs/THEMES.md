# 主题系统

[English](THEMES.en.md) | 简体中文

本项目有**两套并存的主题系统**，服务不同场景：

App 安装主题优先 Wi-Fi，Android 失败后自动回退 USB，iOS 仅用 Wi-Fi。两条路径使用同一 `OBDT` 主题流，先完整接收、校验并解包到临时目录，再通过恢复日志替换；失败保留当前主题，App 不提前删除。固件确认安装成功后自动重启，App 不重复发送重启。删除当前主题也使用同一传输选择，删除成功后单独请求重启；重启失败只提示手动重启。

| | 编译期主题（TOML）| 运行时主题（SD 卡）|
|---|---|---|
| 改什么 | 8 个装饰色 + 表框/指针/表盘素材（换皮，不换布局）| 颜色 + 素材 + **自定义表盘页面与布局**（layout.json）|
| 怎么装 | 主题文件夹编译进固件，重新刷固件 | 编辑器导出主题 ZIP，通过网页 USB 安装到 SD；App WiFi OTA 保持兼容 |
| 怎么切 | 随固件构建确定；普通用户不能在仪表上切换 | 通过网页或 App 安装、选择，设备从 SD 读取并重启生效 |
| 适合谁 | 想快速给内置页面换配色 / 换素材 | 想自己定义表盘页面组成与数据绑定 |
| 来源 | [themes/](../themes/) | 主题编辑器（`obd_theme_store`）导出的 `<id>.zip`（含 `theme.bin`、规则和视频资源），见[主题编辑器契约](../contracts/theme-editor-contract.md) |
| 安装方式 | 开发者重新编译固件 | 网页 USB 一键安装，或 App OTA（固件管理 SD 主题库）|
| 生效时机 | 重启 | USB 安装启用、APPLY 和 OTA 安装后**自动重启** |

两套系统的页面可以协同：运行时主题**声明了页面**时，开机跳过内置表盘页（省 40–60 KB RAM），
主题页面进入轮播环（GEAR 页下滑进入，详见 [USER_GUIDE.md](USER_GUIDE.md#页面导航)）；
没有页面的运行时主题只提供取色默认值，内置页面照样创建，继续用编译期调色板；
没有选择主题、缺卡、文件缺失、清单损坏或解析失败时自动回退内置默认主题；保留已保存的选择。

网页的主题安装和“删除当前主题”均通过 ESP32-S3 原生 USB，不要求设备地址、token 或 WiFi OTA。删除会先释放主题页面与资源，再移除当前 `/OBD/THEMES/<key>/` 目录（含 `theme.bin`、规则、图片、字体和视频）及保存的选择；点击“删除当前主题”后，网页单独请求重启以恢复内置主题；安装新主题时则先自动清理当前主题，无主题时跳过，上传并启用新主题后才重启。其他主题和公共开机动画保留。需先更新支持 USB 管理的固件；无卡或删除失败会显示错误，暂时忙碌可自动重试。

## 一、编译期主题（TOML）

**不用写任何 C 代码** —— 一个文件夹、一份清单、一行登记。

```
themes/
├── registry.txt           # slot -> id，只能追加
├── _TEMPLATE/             # 复制这个开始
├── builtin/               # 固件自带（default / amber / ocean）
└── community/             # ← 你的主题放这里
```

### 能改什么

**只换皮，不换布局。** 8 个装饰色角色（必填）+ 3 类美术素材（可选）。
元素位置、字号、页面排布不在范围内（那是 20 多个 `ui_ScreenPageXxx.c` 的事）；
字体刻意排除 —— 换字体等于换字符尺寸，等于换布局。

| 角色 | 用在哪 |
|------|--------|
| `bg` | 屏幕/页面背景 |
| `ring` | 外圈表框 |
| `arc_track` | 仪表弧线底轨、滑块凹槽（"还没走到"的部分）|
| `arc_indicator` | 仪表弧线进度、滑块填充（"已走到"的部分）|
| `text_primary` | 数值、主文字 |
| `text_secondary` | 提示文字、单位、小标签 |
| `needle` | 指针页的指针 |
| `panel` | 面板/列表/滚轮背景 |

### 不能改什么

语义色全局固定（`ui_theme.h`），任何主题都不许动 —— 装在车上的仪表，
红色必须永远意味着"出事了"：

| 宏 | 值 | 含义 |
|----|----|------|
| `UI_SEM_FLASH` | `0xFF0000` | 转速报警全屏闪烁背景 |

### 制作四步

```bash
# 1. 复制模板
cp -r themes/_TEMPLATE themes/community/sunset

# 2. 填 themes/community/sunset/theme.toml
```

```toml
id   = "sunset"        # 必须和文件夹名一致
name = "SUNSET"        # 设置页显示名，1~10 个大写字符

author      = "your-github-handle"
description = "Warm orange face with a deep purple ring."

[colors]
bg             = 0x140800
ring           = 0x6A2C8A
arc_track      = 0x3A1810
arc_indicator  = 0xFF7A18
text_primary   = 0xFFE0C0
text_secondary = 0x9A6440
needle         = 0xFF3020
panel          = 0x2A1408

[bezel]
style_id = 0

# 可选素材（有什么写什么，没声明的继续用代码画 + 颜色角色）
[assets]
ring   = "assets/ring.png"
needle = "assets/needle.png"
needle_pivot_x = 24      # 指针旋转中心（根部轴心），从左上角算像素
needle_pivot_y = 12
dial   = "assets/dial.png"
```

```bash
# 3. 登记：registry.txt 末尾追加一行（只能追加！）
echo "3  sunset" >> themes/registry.txt

# 4. 编译
idf.py build flash monitor
```

编译期主题随固件构建提供，用户不能在仪表上单独切换。开发者可运行生成器验证
配置（错误会指到具体行号）：

```bash
python3 tools/gen_themes.py            # 重新生成
python3 tools/gen_themes.py --check    # 只校验不写文件（适合 CI）
```

### 为什么 registry.txt 只能追加

NVS 存的是**槽位号**（`theme_cfg.theme`），不是主题名。一旦调换顺序，排在后面的主题槽位
集体位移 → **所有已升级的设备被静默换成另一个主题**，而且本地测试发现不了。所以：

- 只能在末尾追加，不能改号、调序、删行
- 槽位 0 必须是 `default`
- 废弃主题时行和文件夹都原样保留；只删文件夹会让构建失败

生成器在构建时强制检查以上规则，违反直接编译失败并提示改法。

### 美术素材规格

| 素材 | 尺寸 | 透明通道 | 编译后大小 | 替换掉什么 |
|------|------|----------|-----------|-----------|
| `ring` | **正好 360×360** | 需要（中间镂空）| 380 KB | 外圈表框 |
| `needle` | ≤ 360×360 | 需要 | 宽×高×3 B | 指针页的指针 |
| `dial` | **正好 360×360** | 忽略 | 253 KB | 页面背景 |

- **指针必须画成朝右（东）**：LVGL 角度 0 = 原样绘制，画朝上会整体偏 90°
- **空间是硬约束**：所有已注册主题的素材都会被链接进固件（`g_ui_themes[]` 全量引用，
  `--gc-sections` 丢不掉）。一整套约 645 KB，总预算 **1536 KB**（`gen_themes.py --asset-budget`），
  超限构建失败并列出每个文件占用。ota_0/ota_1 各 3 MB，固件本身约 2 MB
- 素材转换需要 Pillow（`pip install Pillow`），但**只在 PNG 变动时**才跑 —— 转换出的 C 文件
  入库，生成器靠源图 SHA-256 判断是否需要重转；生成的 `main/export_path/theme_assets/` 不要手改

### 配色建议

- `arc_indicator` 明显亮于 `arc_track`，否则看不出走了多少（同色会被生成器警告）
- `text_secondary` 比 `text_primary` 暗一点，但开车瞄一眼还得看得清
- `bg` 用很深的颜色 —— 亮背景在夜里晃眼

### 分享

主题文件夹放进 [`themes/community/`](../themes/community/)，可附一张同目录
`preview.png`（拍屏幕即可），PR 标题写 `theme: add SUNSET`。

### 框架内部（改框架才需要看）

- **生成流水线**：`registry.txt` + `theme.toml` → `tools/gen_themes.py`（CMake configure 阶段，
  在 `idf_component_register` 之前）→ `main/export_path/ui_theme_generated.c` +
  `theme_assets/theme_*.c`。`registry.txt` 和所有 `theme.toml` 都在 `CMAKE_CONFIGURE_DEPENDS`
  里，新增主题必触发重新生成；生成器只在内容变化时重写输出，避免无谓全量重编
- **主题状态**：`ui_theme.c` 管活动主题与 NVS 持久化；`ui_init()` 在建任何屏幕前调
  `ui_theme_init()`，所以每屏创建时即取到主题色。页面取色用
  `ui_theme_color_lv(role)` / `ui_theme_color(role)`，不要硬编码 `lv_color_hex()`
- **加颜色角色**：`ui_theme.h` 的 `ui_color_role_t` 末尾（`UI_COLOR__COUNT` 前）→
  `gen_themes.py` 的 `COLOR_ROLES`（同序）→ 所有 `theme.toml`（缺角色直接构建失败，不会静默变黑）
- **加素材类型**：`gen_themes.py` 的 `ASSET_KINDS` + `ui_theme_t` 末尾加字段 + 消费方留 NULL 回退
- **预留字段**：`ui_theme_t` 已有 `dial_face` / `font` / `bezel`（现为 NULL），新能力一律
  往结构体末尾追加，指定初始化器自动补零，旧主题不用改
- **格式细节**：`CONFIG_LV_COLOR_16_SWAP=y` 所以 RGB565 按大端 `(hi, lo)` 输出；
  指针不能用 `LV_IMG_CF_ALPHA_8BIT`（旋转绘制路径下颜色未定义），所有素材用
  `TRUE_COLOR_ALPHA` / `TRUE_COLOR`。`theme.toml` 由内置的受限 TOML 解析器读取
  （ESP-IDF 自带 Python 3.8 没有 `tomllib`），支持注释、`[section]`、`key = value`
  （字符串/十进制/0x 十六进制），超集直接报错并指行号

## 二、运行时主题（SD 卡）

固件提供数据（`signal_store`）、主题引擎与系统页（设置/OTA/蓝牙）；自定义主题的
图片、字体、页面布局和主题视频全部从 SD 读取，不写入 Flash 媒体缓存。
开机动画独立于主题；旧网页上传仍写公共 SD 目录。
固件仍保留内置默认界面和编译期主题，供缺卡或资源无效时使用。
NVS 只保存当前主题 key；规则与标签覆盖以 SD sidecar 为权威副本。旧 config sidecar 在 SD 缺失时迁移一次。

```text
/OBD/THEMES/<key>/
  theme.bin
  sidecar.json
  rpm.obv                  # 可选普通主题视频
/OBD/BOOT/boot.obv         # 网页上传流程的公共开机视频
/OBD/BOOT/boot.jpg         # 公共回退静态图
/OBD/BOOT/bootmedia.raw    # 旧格式开机动画
/OBD/VIDEO/rpm.obv         # 可选共享主题视频
```

`theme.bin` 内含 16 KB manifest、images/fonts 与各页 layout；图片和字体仍需按二进制
格式打包，不直接加载任意 PNG/TTF。主题视频放在对应主题目录；`/OBD/VIDEO` 是可选的
共享主题视频回退目录。VIDEO 模式读取公共 SD `/OBD/BOOT/boot.obv` → `boot.jpg` → 旧格式
`bootmedia.raw`。网页开机动画上传流程继续写入公共 `/OBD/BOOT/`，新文件提交后删除其他旧格式动画；传输中断或校验失败时保留已有动画，旧文件清理失败会提示错误。静态图显示 2.5 秒。
旧 raw 动画的播放时长由 `frame_count/fps` 计算，不采用 manifest 的 `duration_ms`，避免时长不一致时停留在末帧。
JPEG 使用 baseline 格式，宽高均不超过 360 px。
主题包不再受旧 4 MB 分区限制；仍受 SD 空间、格式数量限制和运行时 RAM 预算约束。

### 受保护的启动页

以下页面**永远不参与主题化**，始终用固件内置实现，主题清单里把它们列到
`theme_pages` 会被跳过并记日志：

| 页面 ID | 内容 |
|---------|------|
| `logo` | Sky Gauge Logo（品牌一致性）|
| `intro` | RACE AS ONE 开机动画（NVS `intro_enable`：0=OFF 1=RACE 2=VIDEO）|
| `boot_video` | 受保护的开机控制器；只读取公共 SD 开机目录；播放器是 `media/boot_video` |

启动控制器由固件保护，与主题选择无关。视频必须通过完整 OBV1 校验，静态图必须能由 JPEG
解码器完整解码；公共媒体无效或不存在时跳过自定义动画。

### theme.bin 格式

`theme.bin` 由主题编辑器（`obd_theme_store`）导出，不是手写目录；固件只认文件本身的
二进制布局（代码：`main/theme_engine/theme_loader.c`、`theme_internal.h`）：

```
[0, 16 KB)   manifest JSON（cJSON_ParseWithLength 解析，尾部 0xFF 填充）
[16 KB, …)   images + fonts + 每页 layout（偏移/长度由 manifest 给出）
```

要点与限制：

- 首字节是 `0xFF` 或 `0x00` → 视为无可用主题，用内置默认主题
- `schema_version` 必须精确等于 `"1.0"`，否则 `ESP_ERR_NOT_SUPPORTED`，回退默认主题
- `theme.id` 必填，≤64 字符；`name` / `version` / `author` 超长时按 UTF-8 字符边界截断
- `assets.*`：`format` 为 `rgb565` / `rgba8888` / `lv_font_bin`，未知格式整条跳过；
  宽高 ≤2047 px；`size` 必须等于 `width*height*每像素字节数`；偏移 ≥16 KB；重名素材取第一个
- `pages.theme_pages[]`：`{id, layout_data_offset, layout_data_size}`，单页 layout ≤64 KB；
  重复 `id` 取第一个；`id` 为 `logo` / `intro` / `boot_video` 的页按上一节规则跳过
- 颜色拿不到时回退内置默认调色板
- 容量上限：≤32 页、≤16 张图、≤16 个字体；每页 ≤128 个元素、≤32 个数据绑定

字体是 `lv_font_bin`。'F' 文件系统驱动在 `lv_font_load` 期间从 SD 读取对应字体段到
临时 PSRAM，关闭时释放临时段；LVGL 字体对象保留到主题卸载。失败则记日志
"font '%s': lv_font_load failed, built-in font used" 并退回内置字体。
`theme_load()` 在主题页面对象存活或后台启动页准备任务尚未结束时拒绝重载；图片读取任务结束后才允许
切换/删除主题，避免 SD 文件与后台读操作竞争。

### 主题模式：有页面 vs 没页面（`main/export_path/ui.c`）

内置表盘页（Gear/Rpm/Speed/Temp/OilPressure/Needle）只有在主题 **id 不是 `default`
且声明了至少一个 `theme_pages`** 时才会被跳过（省 40–60 KB RAM）；开机直接进主题默认页
（`id` 为 `main_gauge` 的页，没有则第一页），建页失败回退内置默认页。主题页面轮播里左右
滑动切换页面，划过首尾进入 Info（EasterEgg）页；Gear 页下滑同样能进主题首页（只要
`theme_pages` 非空）。默认主题页的图片在 Logo / 开机动画期间由后台任务读取和转换，启动画面
保持显示；开机视频首帧完整传输到 LCD 后才替换 Logo。全屏播放期间接管 LVGL 刷新回调，防止切页或布局更新自动恢复刷新后清黑屏幕、争用 DMA 缓冲；解码器释放屏幕和缓冲后才恢复正常刷新。若动画先于主题资源准备结束，播放器释放后恢复 Logo，页面就绪后再创建并切换页面，
透明图片转换和视频播放都不会被页面创建阻塞；准备早于视频开始完成时可在 Logo 期间建页。主题包分块读取通过文件描述符 `read` 和内部 DMA 缓冲批量读取，避免本平台 `_IONBF` + `fread` 的逐字节补充开销；慢读取日志分别记录缓冲等待、实际读取与回调耗时。开机视频解码失败或被中止时恢复 Logo，主题准备失败时回退到内置页。主题页面上的图片、视频和其他子控件会把
手势冒泡到页面根对象，因此在任意主题内容区域左右滑动都能继续轮播。完整导航见
[USER_GUIDE.md](USER_GUIDE.md#页面导航)。

LCD 输出还包含 ESP-IDF 5.5.3 SPI bus-lock 的上游唤醒修复，防止跨核请求在 DMA 中断退出时永久等待；LCD 低速探测句柄在注册正式句柄前释放。修复只替换构建目录内的 SDK 源码副本，安装的 SDK 不变。实机同一 360×360 RGBA 图片准备约 238–240 ms；连续 20 次 USB 复位均完整播放 100 帧 OBV2 并进入主题页。这是该设备和资源的测量，不是所有 SD 卡、图片和视频的耗时保证。

**没有声明页面的主题**：目前代码里 `colors.*` 只是主题自身页面元素的取色缺省值，主题
没有页面时根本用不上——**不会**改变内置页面的配色，内置页面始终用编译期主题色。

### Sidecar（规则 + 覆盖）

主题编辑器的规则（告警/变色/动画）和标签覆盖（旋转、方向、数值显示格式）不进
`theme.bin`，单独存一份精简 JSON：

- 位置：SD `/OBD/THEMES/<key>/sidecar.json`（`<key>` = `storage_theme_key(theme.id)`），是唯一权威副本；
  安装/删除需要 SD 卡。旧 config 分区 `/themes/<key>/sidecar.json` 只在 SD 文件缺失时迁移一次，
  成功后删除旧副本
- 输入可以是精简格式本身（`"format":"gauge-sidecar/1"`），也可以是完整的
  `<id>.gaugeproj.json`（流式过滤，边读边丢图片/字体等大字段）
- 限制（`theme_sidecar_core.h`）：精简后 ≤64 KB；≤32 页；每页 ≤128 个 element id；
  单条 element id ≤128 字符；单个 element/rule/overlay 条目 ≤16 KB；超长字符串边读边丢（>4096）
- 可选 `asset_files`：素材名 → gaugeproj 文件名，供 `vid_` / `video_` 元素用 `set.asset`
  规则切换视频
- 安装失败：`ESP_ERR_INVALID_ARG`（JSON / format / theme-id 不对）、`ESP_ERR_INVALID_SIZE`
  （"sidecar too big: reduced form exceeds 64 KB"）、`ESP_ERR_NO_MEM`
- 安装会返回一份配对报告：页数/规则数、截断计数、`not in theme.bin: ...`、每页
  matched/missing/kind mismatch、未知资产/来源、预计因 PSRAM 预算被跳过的元素名（最多列 8 个）；
  末尾一行固定是 "applies on the next page build; bin-only installs (app/store/web flash) have
  no overlay"；报告太长时以 "..." 结尾
- API：`POST /api/v1/theme/sidecar`（分块上传；≤64 KB 走 PSRAM，更大的流式写 SD 临时文件，
  保存前都要求 SD 卡；没插卡则 409 `sd_unavailable`；整体上限 32 MB，超了 413；格式不对
  422 `invalid_sidecar`；成功 `{"ok":true,"size":N,"report":"..."}`）、
  `DELETE /api/v1/theme/sidecar[?theme=<id>]`（不带参数删当前主题的）。`/api/v1` 需要
  `X-OTA-Token`。SD 导入 `*.gaugeproj.json` 同样当 sidecar 安装（`sd_import.c`）

### PSRAM 预算与跳过顺序

建一页时素材总量按是否含视频元素分两档预算（`theme_img_cache.h`）：**不含视频 2560 KB，
含视频 1536 KB**。超预算的分配顺序：

1. 指针及其所有变体 —— 必须保留
2. 规则目标图（会被规则改变外观的图片）—— 必须保留，它们的染色变体也算进预算
3. 装饰性图片按从下到上的层叠顺序分配，预算不够先砍最上层的；装饰性图片还必须
   给系统留出 512 KB 空闲 PSRAM（`TE_PSRAM_RESERVE`）

被砍的素材记日志 "'%s' skipped: over the page budget / PSRAM reserve"。
所有图片（包括未染色的 `rgb565`）都从 SD 读取并持有 RAM 像素，计入缓存预算；
不再有 Flash mmap 零拷贝。缓存未命中时还需要临时源数据和可能的缩放缓冲，因此
包大小不等于页面 RAM 用量。染色变体超过 128 KB（`TE_TINT_BAKE_MAX`）时不预烘焙，
改用运行时实时上色。

### SD 主题库存储

SD 卡 `/OBD/THEMES/<key>/theme.bin` 是固件管理的运行时主题源。用户通过网页或 App 安装、选择主题，
无需直接访问 SD 卡。`<key>` 由
`storage_theme_key(theme.id)` 生成（替换不安全字符、处理前后点与 DOS 保留名，≤64 字符）。
可直接复制到该目录，或将 `*.bin` 放入 `/OBD/IMPORT/` 自动入库；导入后留下 `.ok` 便签。
WiFi OTA 同样直接安装到 SD。旧 Flash 主题只作为升级迁移源，已有 SD 文件不会被覆盖，
已有主题选择也不会被旧资源替换。

主题编辑器导出的 `*-sd.zip` **不是固件可直接读取的安装文件**。在电脑上将 ZIP
该包用于网页或 App 导入，不要求用户手动整理 SD 文件。
包内 `theme.bin` 和普通主题视频位于 `/OBD/THEMES/<key>/`，规则 sidecar 位于
`/OBD/IMPORT/`；固件扫描器导入 sidecar，主题库直接从 SD 主题目录读取主题数据和媒体。
不要把 ZIP 本身放进 `/OBD/IMPORT/`。主题视频按资源 key 导出到主题目录，使用 manifest
引用的名称；视频和主题图片、字体均存储在 SD。编辑器媒体资源面板可以用图片或视频做预览，
但开机动画不属于主题包；网页原有动画上传流程保持不变并写入公共 SD `/OBD/BOOT/`，
与当前主题独立。

主题通过网页或 App 选择；仪表不提供主题选择或 SD 卡管理页面。以下为固件内部应用主题时的处理行为：

1. 删除主题页面对象、`theme_unload()`。
2. 显示 "Loading theme..." / "Loading theme NN%"；后台校验 SD 包并提交 NVS 选择，500 ms 轮询状态。
3. 成功显示 "Theme selected, restarting"，约 1.5 秒后重启并直接读取 SD。
4. 失败显示 "Theme selection failed: <reason>"，重新加载旧选择或内置默认主题。
5. 繁忙显示 "Busy, try again"；无有效包显示 "Not a usable theme.bin"。

切换不擦写 Flash 媒体分区，不复制整个包到 PSRAM。OTA、缺卡或其它存储任务运行时拒绝切换。
旧版中断的 Flash 写入标记会转换为 SD 选择；缺卡时保留标记等待重试。
普通 SD 导入不允许覆盖当前选中的包，应先切到其它主题；OTA 在释放主题页面后可更新该包。
开机缺卡会回退内置界面，插卡后可再次 APPLY。运行中拔卡时已有图片缓存可能继续显示，
后续页面或素材读取会失败，不保证立即切换整套界面。

### 主题视频

主表和从表使用两块 20 行 LCD DMA 缓冲，较独立模式的 40 行缓冲节省 28,800 字节内部 RAM，给 ESP-NOW 与按需创建的视频任务留出空间；独立模式仍优先使用 40 行缓冲。视频任务栈保留在内部 RAM，创建失败时日志记录所需栈大小、内部 RAM 可用量与最大连续块。

主题里 id 以 `vid_` 或 `video_` 开头的图片元素会被当成视频元素：图片本身是封面图
（poster），key 是去掉前缀后的部分。查找顺序是 `/OBD/THEMES/<theme_key>/<key>.obv`，
再 `/OBD/VIDEO/<key>.obv`（供多个主题共享）；都没有就一直显示封面图。`visible` 规则可以暂停视频，
`asset` 规则按 sidecar 的 `asset_files` 切到另一个文件名（不带目录和扩展名）。主题
视频默认循环播放，也可按绑定数值定位帧。同一时刻只解码一路，由最上层可见且不透明度大于 0 的视频图层使用播放器，其余视频显示封面。
主题目录与视频 key 均支持最多 64 个字符；播放器路径缓冲区可容纳完整的主题视频 SD 路径。

循环主题视频的 SD 压缩帧预读目标为约 2.5 秒（另留两帧空间），ring 上限为 2 MiB；短视频不会分配超过整个视频所需的空间。分配前为双帧显示缓冲、OBV3 alpha 临时平面及额外 512 KiB 留出 PSRAM，内存不足时缩小 ring。实际缓存时长随压缩码率和可用内存变化，首次播放仍在约 400 ms 帧水位、ring 满或读到结尾时开始，不等待填满全部缓存。播放开始后若 ring 读空，主题视频读到下一帧就续播，不再每次等待补足 400 ms 水位，以避免持续读取较慢时形成反复成段播放和停顿。循环播放按源视频时间轴调度，仅显式设置 `target_fps` 时限帧；取消默认 24 fps 上限以及每两帧、三帧、四帧显示一次的整档降帧。等待界面接收上一帧后重新检查时限，只跳过已落后超过一个源帧间隔的帧；持续严重落后时重设时钟以保证画面继续更新。较长预读可缓解 SD 读取抖动，不能提高 JPEG 解码或透明合成的硬件吞吐量；数值定位视频与 OBV2 开机动画使用各自原有的缓存和时序策略。

主题视频的读卡和解码任务低于 LVGL 与 OBD 轮询任务，避免连续合成播放同时压住两个实时任务，使界面交接停帧或实时信号过期；PSRAM ring 仍提供预读，ring 满时阻塞等待消费者释放空间。全屏开机动画保留独立的高优先级路径，因为它直接向面板推送。视频文件通过文件描述符 `read` 批量读入内部 DMA 缓冲，再复制到 PSRAM ring；缓冲优先申请 16 KiB，内部 DMA 堆不足时依次尝试 8、4、2、1、0.5 KiB，仍不足则日志会记录可用量和最大连续块。帧间填充和缓冲范围内定位保留预读数据，跨范围定位才重新读取，避免目标 newlib stdio 逐字节补充与反复丢弃预读。开机动画可分块解码并通过 DMA 直接送屏；主题视频需要解码完整帧，再经 LVGL 与其他图层合成，性能不能仅凭缓存时长比较。OBV3 帧的 alpha 平面若完整且全为 255，则直接保留 RGB565，不展开逐像素 alpha；真正透明的帧仍使用 RGB565+alpha，同一视频可逐帧切换，已有主题无需重新导出。界面接收视频帧时立即就绪显示刷新定时器，避免额外等待普通刷新周期。播放器每约 5 秒记录 `queued` 帧率、解码耗时、等待 UI 的耗时及累计丢帧 / 缓存欠载数；`queued` 是解码提交速率，不代表屏幕实测帧率；`UI frame gap` 记录界面接收帧的平均 / 最大间隔，用于识别成段停顿，亦非 LCD 完成刷新计数。同一周期还记录 `SD` 有效读取吞吐量、逐帧读取平均 / 最大耗时及读取帧数 / 字节数；读取计时包含定位和 SD 缓冲等待，不含 ring 空间等待，吞吐量按累计读取耗时计算。

快速切换视频时，新读卡任务等旧任务释放文件与 DMA 缓冲后再开始；等待在后台进行，不让界面线程等待 SD I/O。SD 卡未挂载或视频素材名无效时，保留封面，素材恢复后可以重新播放。

主题视频容器使用自定义的 **OBV1/OBV3**（`main/media/obv1_format.h`）。
旧版或外部普通视频 OBV1 使用 `[64B 头][8B × 帧数 的帧索引][JPEG 帧数据]`（版本 1）；编辑器新导入的视频统一使用 OBV3，
每帧数据为 `[u32 JPEG 大小][u32 alpha 大小][JPEG][PackBits alpha 平面]`。宽高 8..360 且是 8 的倍数，
最多 36000 帧，OBV1 JPEG 帧 ≤128 KiB、OBV3 帧 ≤256 KiB，用 CRC-32 校验。固件只在主题合成播放器中
解码 OBV3，并把 JPEG 颜色和 alpha 合成为 LVGL RGB565+alpha；OBV1 和已有主题保持兼容。

主题编辑器工具栏的“导入视频”按钮打开配置窗口，使用本地 FFmpeg WebAssembly 转换为 360×360、24 fps。导入时保留源视频的 alpha 通道，并用独立 PackBits 平面生成 OBV3；不含透明度的视频也使用 OBV3（alpha 平面会压缩存储）。封面合成为 PNG，编辑器画布和固件播放器都按逐像素透明度显示。编码支持取决于浏览器版 FFmpeg，损坏或不支持的输入会报错；源视频不会上传服务器。

编辑器移除独立的“资源库”入口；通过工具栏导入图片或视频后，素材直接出现在画布和图层列表中，随主题 ZIP 一起导出。同名图片或视频可以重复导入，编辑器会在完成解码后按当前项目自动分配唯一内部标识（视频重名时追加 `_2`、`_3` 等后缀），不会覆盖原有素材或事件引用；删除图层后再次导入也不需要手动重命名文件。点击顶部主题名称可编辑主题信息；选中文字后，在字体属性中点击“导入 / 管理自定义字体”进入字体管理。

编辑器按“设计 → 数据 → 事件 → 预览”组织操作，并显示当前步骤提示。左侧添加工具显示文字名称；未选中组件时，右侧提供已绑定数据的转速、车速和水温基础组件，添加不会覆盖现有内容且可一次撤销。设计属性先显示组件名称与外观，精确坐标和内部 ID 收入“位置与高级设置”；数据面板可为固定文字直接绑定车辆数据，数值转换和文字映射默认折叠。预览可展开底部模拟器拖动数值检查。画布默认随可用空间适配，支持手动缩放与恢复适应；工具栏分行放置显示选项、尺寸及缩放，对齐与排列默认折叠，避免窗口变窄时重叠。

编辑器草稿通过浏览器 IndexedDB 一起保存工程与视频文件，显示“已保存”后刷新可恢复；保存失败会明确提示。顶部“保存”下载含图片、字体和视频的 `<id>.gaugeproj.zip` 工程备份，“打开”可恢复工程 ZIP 或旧 `.gaugeproj.json`；工程 ZIP 用于继续编辑，导出的主题 ZIP 用于设备安装。旧草稿或 JSON 缺失的视频会逐个显示“补回视频”按钮，选择原视频或主题 OBV1 `.obv` 后保留原有图层位置与事件设置。主题导出只要求并打包图层或事件实际引用的视频，删除图层后留下且不再被引用的记录不会阻止导出。

导入窗口内显示转码进度条、当前阶段、百分比及可统计的帧数，覆盖解码、逐帧转码与生成主题视频。加载解码器等无法计算总量的阶段显示滚动进度；完成后显示时间轴预览，失败时显示原因，处理期间不能重复添加。补回视频时仍在画布上方显示进度。

#### 数值驱动动画

导入窗口的“播放方式”可选“循环播放”或“跟随数值”。选择后者，设置绑定数据、起始值、结束值和数值步长；结束值必须大于起始值，步长不能为负。上下对齐的视频时间轴与数值时间轴显示缩略图和当前对应值，可拖动或播放检查映射，再点击“添加到画布”。选中已有视频图层后，可在属性中修改绑定与查看时间轴。

起始值对应第一帧，结束值对应最后一帧，中间按比例选取最近帧。数值下降时画面回退，超出范围停在首尾；数据无效时保留上一次位置，首次无数据从第一帧开始。编辑器模拟数据与固件蓝牙连接扫表都会驱动绑定；已有显示、透明度及切换素材事件继续作用于该图层。设备异步读取并解码目标帧，快速变化时可跳过过期目标，不保证显示经过的每一个中间帧。数值变化仍映射到同一帧时，不再唤醒读卡和解码任务；跨帧变化（包括快速往返）仍通知处理，减少油门相关数值轻微抖动时的无效调度。此优化不提高源视频帧率，也不改变已有目标帧去重策略。

步长 `0` 使用全部现有帧；正步长先将数值按起始值对齐到最近的步进值，再选择帧，范围终点始终可达。例如 6 秒视频绑定 `0–6000` RPM，步长 `100`，则 `3000` RPM 对应视频中点附近的帧，`6000` RPM 对应最后一帧。步长不会生成新帧：导入的 24 fps、6 秒视频约有 144 帧，实际可用画面仍取决于源素材和转换结果。

布局 JSON 为视频图片元素追加以下可选字段（下例省略几何及封面字段）：

```json
{
  "type": "image",
  "id": "vid_rpm",
  "video_playback": "value",
  "data_source": "obd.rpm",
  "range_min": 0,
  "range_max": 6000,
  "video_step": 100
}
```

未声明 `video_playback: "value"` 时保持原有循环行为；绑定仅用于 `vid_` / `video_` 图片元素。`data_source` 使用标准信号名，`range_min`、`range_max` 和 `video_step` 使用信号原始单位；网页按显示单位编辑，例如电压内部值 `120` 显示为 `12.0 V`。无效范围不会启用数值驱动。两种主题播放方式均使用带帧索引的 OBV1，OBV2 仅用于全屏开机动画。

```bash
python3 tools/make_video.py boot INPUT -o boot.obv            # 开机视频，默认 360px/4:2:2/Q75/24fps
python3 tools/make_video.py theme INPUT -o rpm.obv --size 240x240 [--poster rpm.png]
python3 tools/make_video.py inspect boot.obv                  # 打印头部信息
python3 tools/make_video.py verify boot.obv                   # 校验 CRC 与每帧
python3 tools/make_video.py legacy INPUT -o bootmedia/slot_a [--raw bootmedia.raw]  # 老的 delta_varint 开机动画
```

需要 Pillow（`pip install Pillow`），视频输入还需要 ffmpeg。

网页本地和社区新上传的开机动画使用 **OBV2**，主题视频继续使用 OBV1。OBV2 沿用 `OBV1` magic 和 64B 头，
`version=2`、`fps=0`、`timescale=1000000`；16B 索引项为 `offset,size,timestamp_us,duration_us`。
时间戳从 0 连续递增，单帧间隔 ≥16666 µs，`duration_ms` 为总时长向上取整，最多 36000 帧，
单帧 ≤128 KiB、文件 ≤256 MiB，一秒压缩帧窗口加环绕余量 ≤1.25 MiB。头、索引和帧数据各有 CRC-32。
超过 48 KiB 的帧需要升级到支持 128 KiB 上限的固件；原有小帧动画仍可使用。
浏览器将视频转为 360×360 Q90 baseline JPEG 4:2:0，默认保留源帧时间轴；USB 本地导入保持比例、不裁切，
社区上传按裁剪、缩放和起止时间设置处理，并可显式选择帧率。预算超限时直接报错。固件预读约一秒的压缩帧，SD 顺序读取；360×360/4:2:0 使用整帧解码、双 DMA 缓冲分条推屏，
满足 MCU 对齐和解码自检的素材可使用块解码。OBV2 仅支持非循环全屏开机播放；解码或读卡暂时落后时，仅跳过显示区间已经完全过期的中间帧，
保留首尾帧并按源时间轴追赶，不因连续迟到而提前退出。真实读卡或解码错误仍终止播放。此为格式上限，实际帧率仍需在设备上验证。
网页用 USB `BEGIN_OBV=7` 暂存、校验后安装到 `/OBD/BOOT/boot.obv`。工具的 `boot/theme` 仍生成 OBV1；
`inspect/verify` 可读取两版，旧 BIN/raw 动画继续兼容。

### 安装 / 推送

主题编辑器将原来的 BIN 和 SD 资源包导出合并为 **导出主题 ZIP**，下载一个 `<id>.zip`。
ZIP 包含 `/OBD/THEMES/<key>/theme.bin`、主题的 `*.obv` 视频和
`/OBD/IMPORT/<key>.gaugeproj.json`；图片、字体和布局位于 `theme.bin`，规则来自 gaugeproj。
编辑器会阻止缺少关联视频文件的导出。开机动画独立于主题，仍保存在公共 `/OBD/BOOT/`。

推荐安装流程：插入 SD 卡，使用 ESP32-S3 原生 USB 连接网页刷机页，在 **主题** 区域点击 **从社区选择** 或
**本地上传**。网页校验目录、CRC、主题 ID、数据范围和视频依赖后解包，通过 USB 检测并删除当前主题目录及选择，再按顺序上传主题与资源；没有当前主题时直接上传。删除未成功确认时停止安装。
固件校验 SHA-256，将文件暂存并生成 `sidecar.json`；全部成功后保存主题选择并重启。
无需手动解压或另行启用。首次使用需安装支持 USB 主题包的固件；旧固件会被提示升级。
设备已有主题时也可直接上传替换；网页从刷机模式切回应用时会先重启仪表，随后清理步骤等待开机主题准备或锁忙碌，
每隔 500 毫秒重试，等待预算为 2 分钟，并显示等待提示，无需手动删除当前主题。固件明确标记 `retryable:true` 时可重试；
兼容旧固件未提供该字段、只返回 `theme delete failed` 或 `display busy` 的情况。旧版错误无法区分开机忙碌与真实删除失败，持续失败到期后停止，并提示升级固件获取详细诊断。
新固件附带失败阶段 `stage` 和错误码 `code`；明确 `retryable:false`、其他业务失败或通信异常会立即停止安装。上传 BEGIN 的存储忙碌仍单独等待最多 30 秒。

兼容新版完整 ZIP、旧 `*-sd.zip` 和 STORE / DEFLATE 压缩，也可同时选择旧 BIN、配套 gaugeproj / sidecar JSON
及 `.obv`。仅有 BIN 时保留其中的图片、字体和布局，无法恢复未提供的规则或视频；缺少已声明视频时拒绝上传。
社区新发布主题保存完整 ZIP，历史 BIN 仍可安装；文件内容决定格式。完整固件刷写完成后需重连，再安装主题或动画。

支持同 ID 主题更新：提交前释放正在使用的主题资源，通过暂存目录、旧目录备份和恢复日志替换整个主题目录。
安装失败时回滚；提交过程中断电，下次开机挂载 SD 后尝试恢复旧文件和选择。提交前至少预留
`2 × 上传流大小 + 1 MiB` 可用空间。网页 ZIP 和上传流各限 256 MiB，最多 128 个安装文件。
主机测试覆盖目录替换、校验失败、选择失败回滚与中断恢复，不代表真实 SD 卡的断电可靠性。
网页自动替换会在上传前删除当前主题，因此上述安装事务不能恢复已删除的旧主题；清理后上传失败或中断，下次重启使用内置默认主题，可重新上传。

也可解压 ZIP 到 SD 根目录，保留已有文件；规则在启动时自动扫描导入，但手动复制不自动启用。
网页主题安装使用 ESP32-S3 原生 USB；App 的 WiFi OTA 路径保持兼容。

**WiFi OTA 推送**（设备进 OTA 模式后，协议见
[APP_PROTOCOL.md](APP_PROTOCOL.md#wifi-ota-http-api)）：

- `POST /ota/theme/prepare` — 检查 SD 挂载与可用空间，返回 `storage:"sd"`；PSRAM 字段仅供诊断。
- `POST /ota/theme` — 分块流式写 SD 临时文件，SHA 校验与清单校验后入库、保存选择并自动重启。
- `POST /ota/theme/erase` — 删除当前选中主题的整个 `/OBD/THEMES/<key>/` 目录（含 `theme.bin`、规则、图片、字体及专属视频）并清除选择；下次开机使用内置默认主题。需要 SD 卡挂载；其他主题和公共 `/OBD/BOOT/` 开机动画不受影响。返回 `{"ok":true,"deleted":true|false}`。

主题选择任务运行时，这三个接口和 `/ota/bootmedia` 的首块返回 "theme library busy"。
主题通过 USB、SD 或 WiFi 传输，没有 BLE 主题上传通道。缺卡时媒体上传返回 "SD card required"。

### 运行行为

编辑器的图片和视频属性提供 0–100% 不透明度。事件面板以“当 / 执行 / 恢复”概括规则，透明度事件可直接填写基础值、目标值与过渡秒数；基础值同步到图层属性。浏览器预览支持多个视频同时播放，在首帧解码完成前保留封面，遇到坏帧保留上一帧并继续尝试后续帧。

浏览器的事件与预览工作区使用独立实时时钟推进防抖和渐变；即使预览时间线暂停，手动修改模拟转速等数据仍会在满足条件并经过防抖后触发事件，条件解除后恢复图层基础属性。暂停时间线仍会暂停定时触发器的时间。

预览的规则执行状态区分“已停用 / 等待 / 执行中”，显示数据条件、当前模拟值和动作目标；停用规则可在预览中明确点击“启用规则”。事件列表的状态圆点只显示状态，点击不会切换启停；在事件详情使用“启用规则”开关。若希望转速达到 3500 后视频淡出，需启用规则，条件设为 `obd.rpm >= 3500`，视频基础不透明度设为 `100`、动作目标不透明度设为 `0`，并选择渐变过渡。

- 开机时 `theme_engine_init()` 读取 NVS 选择对应的 SD 包：缺卡 / 文件缺失 / 清单损坏 / 解析失败 →
  自动回退内置默认主题，不会变砖
- 主题页面在屏幕上时，LVGL 任务通常每 16 ms 调一次 `theme_tick()`（动画/告警期间使用对应刷新周期）：读一次
  `signal_store`（键定义见 `contracts/signals.json`）更新数据绑定（只有变化的值才动 LVGL
  对象），再在同一份快照上跑 sidecar 规则并应用差异；没有主题页面在屏幕上时是空操作
- 主题页面显示且处于蓝牙连接扫表期间，数字标签（含自定义字体）与规则评估共享全部 12 个标准 `obd.*` 信号的模拟快照，
  因此数字、各信号的阈值条件和 `change` 规则都可随扫表变化。扫表结束后绑定与规则输入立即恢复为真实 `signal_store` 数据；
  模拟值不会写入或覆盖真实 OBD 数据。车型专属 `veh.*` 信号没有统一量程，因此扫表期间仍使用其实时数据
- 扫表规则仍遵循实际条件持续时间和动画时长：约 1 秒从 0 升到 8000 rpm 时，`obd.rpm <= 3000` 只在上升开始的约 0.4 秒内成立，不能在这段时间完成 1 秒淡出。要在超过 3500 rpm 后淡出，应使用 `obd.rpm >= 3500`。上传主题 ZIP 只更新主题资源，不更新固件；固件建页日志包含规则和目标数量，扫表开始及活动规则集合变化时记录 `sweep rules`（模拟转速、活动掩码、目标数和告警抑制状态），结束时记录恢复真实输入。
- 规则的条件/滞回/去抖/计时状态仍每次更新；活动规则集合相同时复用已排序的动作覆盖表，
  集合改变时重新计算并撤销退出规则的覆盖，重建页面或主题时清除缓存。
  集合与系统告警抑制状态都不变时，还会跳过目标外观的拼装/比较；数据绑定继续更新，
  规则退出、抑制切换和 reset 后首次更新仍应用外观，告警结束仍恢复页面背景。
- 弧线和条形的规则动作 `set.color` 只改变进度/填充色，底轨保留元素的 `bgColor`；即时变色和颜色动画遵循同一规则，避免扫表越过阈值后底轨一起变亮、看起来瞬间满格。规则退出后恢复原进度色。已有主题包无需重新导出，更新固件即可生效。
- 圆弧进度使用完整的 0–10000 数值范围，不套用像素坐标的 8191 上限；扫表和实时数值均可到达满刻度。
- 规则动作的 `set.color` 支持 `animation` 的 `fade`、`keyframes` 和 `strobe`，每个主题 tick
  更新颜色或图片 tint；`change` / `timer` 规则会保持到最长动画时长结束。动画不预生成图片帧，
  `text`、`visible` 和 `asset` 仍即时切换；图片资源切换当前不是 crossfade。
- 图片和视频图层可在 layout 中设置 `opacity`（0–100，默认 100）；规则动作 `set.opacity`
  可指定目标透明度，并用 `animation.mode: "fade"` 与 `durationMs` 在指定时长内渐变。
  条件解除后按相同动画时长渐变回图层基础透明度。主题视频共用一个 JPEG 解码器：固件只播放
  当前最上层且可见、非透明、未暂停的视频；上层隐藏或透明度降至 0 后，下层视频接替播放，
  隐藏视频时其封面也会一起隐藏，不会遮挡下层视频。所有视频封面按必需图像优先缓存，
  不会因装饰图片预算不足而遗漏下层视频的静态画面。不会同时解码两个视频，也不支持视频间实时交叉淡化。
- 标签取字体：先试 manifest 里的 `font_asset`，加载失败退回内置 Montserrat
  12/14/16/26/32/48（先找精确匹配，没有就找最接近的更小号，再没有用最小号 12）；
  要求的字号大于 48 时用 48 号字体 + `transform_zoom = 字号×256/48` 放大
  （LVGL 的 `transform_zoom`，和编译期主题的素材缩放无关）
- 数据缺失或是 NaN 时标签显示 `--`（不显示单位）
- 系统告警优先于主题规则：转速报警全屏闪烁或三连表联动变红期间，主题规则暂停
  （数据绑定仍然在刷新），结束后内置页面恢复调色板背景+表盘，主题页面恢复自己 layout
  里的 `bg_color`
- 页面 layout 与素材从 SD 按段读取；缓存命中不再读 SD。图片转换、裁剪、染色和指针缩放
  使用 PSRAM；等尺寸图片仍持有独立 RAM 像素，页面引用存在时不释放缓存。
  字体和 layout 的读取段在解析后释放。SD 读锁等待最多 1 秒，失败时结束本次加载。
  主机测试覆盖像素/几何一致性、读取失败与分配失败清理，不代表实际 SD/LCD 性能。
- API 见 [main/theme_engine/theme_interface.h](../main/theme_engine/theme_interface.h)

### 分区表背景

当前保留 layout v2 的物理布局：`theme_0`（0x620000，4 MB）和 `bootmedia`
（0xA20000，4.75 MB）只作旧资源迁移源/预留空间，合计 8.75 MiB。
新主题和动画不使用这些分区；本次没有把这部分重新分配给固件或配置区。
地址见 [partitions.csv](../partitions.csv)。已使用 layout v2 的设备可 OTA 更新；
仍用旧分区表的设备需要一次性全量刷写，OTA 不能改分区表。

## 视频提前解码与双缓冲

播放器继续采用 SD 连续预读、PSRAM 压缩帧 ring 和常驻 JPEG 解码器。全屏模式将下一帧的首个 MCU 条带或完整图像提前解码，到源时间点才开始刷屏；两个内部 DMA 条带按奇偶交替，等待上次传输完成后才提交下一条带，不改写在途缓冲。主题叠加模式保留前后台双帧缓冲及 LVGL 交接。OBV2 时间轴同样提前解码，暂停时保留压缩帧并移动时间基准，超时帧按既有规则跳过。解码耗时统计排除等待帧时间点的睡眠。实际帧率仍需在设备上测量；没有硬件测试不能承诺固定帧率。

## 弧形与能量条背景透明度

运行时布局的 arc/bar 支持可选 `bg_opacity`（0–100，缺省 100，越界钳位）；0 隐藏轨道背景，100 保持不透明。弧形使用 LVGL `LV_PART_MAIN` 的 arc opacity，能量条只设置容器的背景 opacity，不改变指示弧、前景条或子对象的整体不透明度。编辑器中的背景不透明度在工程、预览和导出中一致。旧主题保持默认实色；旧固件忽略新字段，因此透明背景需升级固件后生效。

主题社区发布和 ZIP 导出现在共用图片／视频尺寸转换，视频海报同步按图层尺寸生成；视频补齐至 8 像素倍数时采用整数居中，与设备裁切对齐。旧社区包中资源尺寸和布局不同的主题，需要从原工程重新导出／发布；升级固件不会自动改写这些旧文件。自动社区封面的 PNG 像素按仪表圆形裁切。
